UNIVERSAL GEO-CONVERTER PRO — MASTER BUILD INSTRUCTIONS
Chrome Extension | GIS + Geomatics + CAD + Survey + Mining Intelligence

DOCUMENT PURPOSE
Build an advanced, browser-first Chrome Extension that functions as a professional universal conversion, inspection, repair, editing, visualization and export suite for GIS, Geomatics, CAD, Surveying, Cadastral Mapping, Drone Mapping, LiDAR and Mining data.

The extension must be designed as a serious engineering tool, not a simple file-format converter.

PRIMARY OBJECTIVE
Create maximum practical IMPORT support and maximum practical EXPORT support while preserving:
- Geometry
- Coordinates
- CRS/projection
- Units
- Elevations/Z values
- Attributes
- Layers
- Styling
- Labels
- Metadata
- Precision
- Topology
- Spatial relationships
- CAD/GIS semantics wherever the target format supports them

The application must be browser-first, local/offline-first and privacy-preserving. Files should be processed locally whenever technically possible. Do not upload user project data to a server by default.

IMPORTANT IMPLEMENTATION PRINCIPLE
Do NOT fake format support.
A format may only appear as supported when the extension can actually parse/import or generate/export it correctly.
Unsupported features must be reported explicitly in a Conversion/Fidelity Report.

53. INTEROPERABILITY DESIGN RULE
============================================================

The canonical internal model is the heart of the system.

DO NOT build every converter directly against every other converter.

Correct architecture:

FORMAT A
   ↓
IMPORT ADAPTER
   ↓
UNIVERSAL INTERNAL MODEL
   ↓
INTELLIGENCE / QA / EDITING
   ↓
EXPORT ADAPTER
   ↓
FORMAT B

This prevents an unmaintainable N×N converter architecture.

============================================================
57. NON-NEGOTIABLE RULES
============================================================

1. Do not remove existing working functionality while adding new functionality.
2. New features must be additive unless explicitly replacing a defective implementation.
3. Do not hard-code CRS assumptions.
4. Do not silently change coordinates.
5. Do not silently discard attributes.
6. Do not silently discard Z values.
7. Do not silently repair uncertain geometry.
8. Always provide undo for edits.
9. Always provide a conversion/fidelity report.
10. Never claim unsupported formats are supported.
11. Keep sensitive engineering/mining data local by default.
12. Do not expose secrets in exports.
13. Do not freeze the browser during heavy processing.
14. Keep the main UI minimal.
15. Advanced functionality must remain accessible through contextual panels and command search.
16. Preserve source provenance.
17. All geometry-changing operations must be tolerance-aware.
18. Preview before destructive operations.
19. Export only after validation.
20. Test round-trip fidelity for every major converter.
