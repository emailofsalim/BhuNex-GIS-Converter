## Known gaps — deliberate and documented, not bugs

1. **GeoTIFF decodes uncompressed, LZW, Deflate and PackBits only.** JPEG, JPEG
   2000, LERC, WebP and Zstandard are refused *by name*; the georeference,
   extent and footprint of such a file are still read. Multi-IFD pyramids and
   overviews are not read — only the first image. Resampling, raster
   reprojection and DEM products remain Phase 4 work.
2. **LAZ is refused, never mis-parsed.** No codec bundled, so the compressed
   payload is reported honestly (rule R5).
3. **DWG requires the native host.** No browser-native DWG; status states surface
   in the top bar.
4. **DGN / E57 / GeoPackage / FlatGeobuf / GeoParquet / vendor mining formats** are
   adapter contracts only.
5. **Datum shifts beyond the WGS 84 family** and **geoid (orthometric↔ellipsoidal)**
   are not offered — no engine, so no UI for it.

## Structure preservation (rule R16) — how it works

`core/layout.ts` **plans and packages only**; format bytes are still written by the
pipeline. That split is why `tests/structure.test.ts` can assert on paths alone.

- `CirLayer.path` is an array of segments, never a joined string. KML folders nest,
  DXF layer names are flat, GML groups by feature type — the segments are what let a
  writer rebuild real folders.
- `CirDataset.origin` (`SourceOrigin`) records the source path, its directory and the
  archive chain it was extracted from, so `mirror-source` works even for a file found
  two ZIPs deep.
- Three layouts: `single`, `per-layer`, `mirror-source` (`OutputLayout`). Exposed in the
  workspace settings panel next to precision, and persisted in `AppSettings.outputLayout`.
- Invariants held by the layout engine and covered by tests: one layer gets no folder;
  one file is never wrapped in a ZIP; segments are sanitised so `../etc` cannot escape;
  colliding paths get numeric suffixes.
- The whole delivery tree is computed before packaging (`ConversionResult.tree`) and
  rendered in the workspace's **Delivery structure** tab.

| 2026-09-08 | regions from cells, and a flag that was not evidence | **`engines/raster/vectorize.ts`** finishes Phase 4. The failure worth designing against is not a crash but the naive version WORKING: one square per pixel, sixteen million polygons from a 4000x4000 raster, and every internal edge between two cells of the same class drawn as a boundary that does not exist on the ground. It opens, it draws, and it is wrong in a way that looks like detail. So a flood fill finds the cells of a region first and only the boundary of the whole region is emitted — the shape a person would draw. The boundary walk is on the CORNER lattice, where every vertex is an exact integer pair, so two regions sharing an edge produce exactly coincident boundaries rather than ones differing in the last bit and leaving slivers on dissolve; the same reasoning as the contour engine keying its joins on edge identity. | 2026-09-08 | resampling, reprojection, and a silent mislabel | **`engines/raster/warp.ts`**, and the bug that made it urgent. `transformDataset` reprojected every vector layer, left the raster's pixels alone, and then relabelled the dataset with the target CRS — so the output claimed UTM 43N while its pixels sat on the geographic grid they arrived on. A GeoTIFF like that opens, draws, and is in the wrong place by a few hundred kilometres, which is far enough to look like a different dataset rather than a wrong one. It now says so: the raster keeps its own CRS, the mismatch is a named warning with what to do about it, and nothing downstream can read the dataset label and conclude the pixels moved. Four decisions carry the engine. **Inverse mapping.** Walking the source and writing forward is the obvious approach and it is wrong: the transform is not area-preserving, so target pixels the source stretches over receive nothing and the output is stippled with holes. The walk is over TARGET pixels, each centre transformed backwards and sampled. **Bilinear is wrong for categories.** Averaging land-cover class 3 with class 5 gives class 4 — invented, and possibly not in the legend at all. Averaging two elevations gives an elevation. So the default follows the data (`isElevation` → bilinear, otherwise nearest) and the choice is REPORTED rather than assumed. **No-data is not a number.** Bilinear over four neighbours where one is no-data gives no-data, not a three-quarter blend: blending ramps gently down into the hole, and the result contours beautifully and is entirely fictional. **The target grid keeps the pixel COUNT, not the pixel SIZE** — 0.0001 degrees is about 11 m, and a raster reprojected from degrees to metres carrying its numeric pixel size across becomes eleven metres wide. Its edges are sampled rather than just its corners, because a projection bows the edges and a corner-only box clips the bulge. Also refused rather than fudged: a degenerate geotransform, which would otherwise divide by a zero determinant and fill every pixel with NaN in an output that "succeeds". One test expectation of mine was wrong and the engine right — bilinear legitimately cannot fill the outer half-pixel, because it needs four surrounding centres and the border has two; that is now asserted as a border rather than papered over, which is also what distinguishes it from the forward-mapping holes. +0.5 KB zipped. 885 tests (`warp.test.ts` new, 24). Version 1.0.9. |
| 2026-09-08 | batch pause, resume and retry-failed | The last of the open UI work, and the whole design is one sentence: **pause stops the batch STARTING the next file, and never interrupts one already running.** That is not a shortcut taken to save effort. A conversion is a synchronous parse loop inside a worker, and the only thing that stops one mid-file is `Worker.terminate()` — which is what Cancel does, and it throws the work away.
